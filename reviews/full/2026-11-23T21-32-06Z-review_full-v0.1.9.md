## Other Observations

### Application

#### meridian-mcp (Rust MCP server/CLI binary)

**Observability** — _medium_

The absence of logging is deliberate (accepted decision) and serves the secrecy NFR. Nothing compensates for it. X-Request-Id is generated per request but never returned to the agent, so a failed call cannot be correlated with backend logs. There is no opt-in redacted diagnostic mode and no way to tell 'waiting on the backend' from 'hung' during the silent 15-minute evaluation (accepted risk).

Gaps:

- Request id not included in Failed messages or tool results
- No opt-in, secret-redacting diagnostic mode (for example stderr diagnostics behind an env flag that never prints headers or bodies)
- No MCP progress notifications during evaluation (accepted risk; rmcp supports progress notifications via progressToken)

**Testability** — _medium_

review_report.rs is well tested: version detection, no-overwrite, hostile version strings, scratch-only moves and destination resolution. smoke.py is a good black-box protocol test that also asserts schema discoverability. There are no tests for backend.rs reply classification, session semantics, the evaluate poll loop or timeouts. Backend is a concrete struct with no trait seam, which makes mocking HTTP awkward. release.yml never runs `cargo test`, and no PR or push CI workflow was supplied.

Gaps:

- No unit or contract tests for Backend::call (status and code mapping, details formatting)
- No test for the poll loop (RUNNING -> COMPLETE, failure mid-poll, timeout note)
- `cargo test` is not executed in any supplied pipeline
- No contract test against mcp-api.md (e.g. recorded fixtures or a mock server)
